Fix a fatal `unhandledRejection` in the CEP-41 server-side `OpenStreamWriter` keepalive path (process exit 1, every ~9h under load in the reported deployment). When a dead client had multiple open streams, the first writer's probe-timeout teardown evicted the client session; every sibling writer's probe-timeout abort then rejected with `No active session found for client` from `sendNotification`, and the timer callback discarded that rejection. Both keepalive timer callbacks now attach `.catch(() => undefined)`, mirroring `OpenStreamSession` — teardown state is complete before the abort publish, so dropping the rejection is safe. Also fixes the adjacent livelock: an undeliverable keepalive ping (evicted session, relays rejecting the event, transport closing — the relay pool already retries transient failures internally) used to re-arm the idle timer forever, hanging the stream and its deferred response; the writer now aborts with `Failed to send keepalive ping`, matching the client session's policy, while a rejection for a probe the peer already acked still recovers on the next idle cycle. Hardens `ApplesauceRelayPool.rebuild` the same way: a synchronous throw from relay/subscription reconstruction is logged instead of escaping the fire-and-forget rebuild as an unhandled rejection.
